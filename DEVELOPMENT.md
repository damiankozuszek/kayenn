# KAYENN – information for developers

The project language (code, comments, documentation, commit messages) is **English**. The program interface,
reports and printouts are available in **English** (the default after installation) and **Polish** (menu
Language / the command `LANGUAGE`, the change works at once). The texts in the code are written in Polish – the
source language; the English translations are in `kayenn_lang_en.json` (Polish text → English; a key with `{}` is a
pattern). They are applied where the texts reach Qt, so the program logic and the `.kayenn` files always keep the
Polish texts. **A new interface text needs its English entry in `kayenn_lang_en.json`** – `test_language` in the
tests looks for Polish texts left in the English interface. The material database stays in Polish.

## Running from source

Python 3 and PySide6 are required; VTK draws the 3D models on the graphics card:

```
py -m pip install PySide6 vtk
py kayenn.pyw
```

On Windows a double-click on `kayenn.pyw` is enough (macOS / Linux: `python3 kayenn.pyw`). When
PySide6 is missing, the program offers to install it on the first start. Without VTK (or without OpenGL 3.2, e.g. in
a virtual machine) the models are drawn by the basic renderer – the program works the same.

## 3D models

`Canvas3D` paints a list of items with QPainter. The faces of a scene (ground or terrain, building, load layers)
go into one `scene3d` item that `VtkScene` renders with VTK off screen (parallel camera = the program's projection,
lighting, depth peeling for the translucent layers) – one shared off-screen window for the 3D window, the card
previews and the printout. Dimensions, labels, arrows and the legend are painted over it, as before. The engine is
chosen in Plik → Opcje (the console: `RENDERER VTK|BASIC`, the environment: `KAYENN_RENDERER=basic`); when VTK fails
the same faces are painted by QPainter. VTK is the base of the future FEM module (meshes, result maps).

## Checks

The trial run of the built program (`python packaging/build.py`, `--autotest`) checks fonts, scaling, the material
database, the map widget and TLS. The maintainer's internal test suite is not part of the repository.

## Installation packages

GitHub Actions (`.github/workflows/packages.yml`) builds the packages on Windows, macOS and Linux: tests,
PyInstaller, a trial run of the built program (window screenshots as the `screenshots-<system>` artifact), package.

- Locally: `python packaging/build.py` (requires `pip install -r packaging/requirements.txt`; Windows – Inno Setup 6).
- New release: change `APP_VERSION` in `kayenn.pyw` and push a `v<version>` tag – the packages go to a draft
  release in the Releases tab.

## Look on different systems

The program uses its own fonts (Noto, `fonts/` folder), the Fusion style, its own light palette and font sizes
computed as at 96 dpi – so it looks the same on every system.

## Structure

The part names are internal – the user sees only the name **KAYENN**.

| Part | Scope |
|---|---|
| **KAYENN Manager** | main window: project, list of cases, printout, language menu |
| **KAYENN Codes** | code loads: imposed, snow, wind |
| **KAYENN Lab** | own loads, material database (`kayenn_materials_pl.txt`) |
| **KAYENN FEM** | finite element analysis (planned) |

| Folder / file | Contents |
|---|---|
| `kayenn.pyw` | the whole program |
| `kayenn_materials_pl.txt` | bundled material database (Polish, user-editable) |
| `fonts/` | bundled Noto fonts (OFL) |
| `branding/` | wordmark and icon, generated by `branding/branding.py` |
| `packaging/` | PyInstaller spec, Inno Setup script, build script |
